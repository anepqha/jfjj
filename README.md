# jfjj

ربات مدیر (`manager_82.py`) + سلف مشتری‌ها (`95.py`).

## اجرا روی Railway

ایمیج، کد را در `/opt/jafj` نگه می‌دارد و `railway-start.sh` همیشه **همان نسخه**
را اجرا می‌کند؛ Volume فقط داده‌ها را نگه می‌دارد.

| چیز | مقدار |
| --- | --- |
| Builder | Dockerfile (`railway.json` تنظیمش کرده) |
| Start command | `sh /opt/jafj/railway-start.sh` — در داشبورد عوضش نکن |
| Volume | روی `/app` مانت کن (یا `DATA_DIR=/data` بده) |

چرا این‌طور: اگر Volume روی `/app` باشد، فایل‌های داخل ایمیج **پنهان** می‌شوند و
نسخه‌ی قدیمیِ مانده در Volume اجرا می‌شود؛ نتیجه‌اش این بود که هیچ دیپلویی اثر
نمی‌کرد و سلف با «فایل 95.py پیدا نشد» بالا نمی‌آمد. `/opt/jafj` داخل ایمیج است
و Volume نمی‌تواند پنهانش کند.

`railway-start.sh` همچنین manager را زیر نظر می‌گیرد: اگر crashes موقتی رخ دهد
(مثلاً FloodWait تلگرام) خودش درجا ری‌استارتش می‌کند تا سرویس کرش‌لوپ نشود، و
فقط بعد از ۵ کرش پشت‌سرهم کار را به سیاست ری‌استارت خود Railway می‌سپارد.

### بعد از هر تغییر کد

حتماً **Redeploy** بزن تا ایمیج دوباره ساخته شود؛ بدون rebuild همان کد قبلی
اجرا می‌شود.

### ⚠️ «فایل 95.py پیدا نشد» / «ریل‌وی قدیمی هنوز روشنه»

این دو در واقع **یک ریشه** دارند: **دو سرویس (یا دو دیپلوی) با یک توکنِ ربات
هم‌زمان به تلگرام وصل‌اند.** تلگرام پیام‌ها و دکمه‌ها را بین هر دو کانکشن پخش
می‌کند؛ گاهی دکمه‌ی «روشن کن سلف» به سرویس جدید می‌رسد (که سالم است) و گاهی به
سرویس/دیپلویِ قدیمی که فایل `95.py` داخل ایمیجش نیست و خطا می‌دهد.

راه‌حل تو (سمت Railway):

1. برو داشبورد Railway و مطمئن شو **فقط یک سرویس** از این ربات وجود دارد؛
   سرویس تکراری/قدیمی را **Remove** کن (یا حداقل دیپلوی قدیمی را خاموش کن).
2. روی سرویس درست، **Redeploy** بزن تا ایمیج دوباره ساخته شود.
3. چک کن استارت‌کامند روی داشبورد دستی عوض نشده باشد: باید همان
   `sh /opt/jafj/railway-start.sh` باشد.

**اگر حساب Railway قدیمی پریده و دسترسی نداری (جی‌میل فیک و…):** سرویس
قدیمی هنوز ممکن است با توکن رباتت زنده باشد و تو نمی‌توانی Remove کنی.
به‌جایش **توکن ربات را عوض کن** تا کور شود:

1. در تلگرام برو **@BotFather** → `/mybots` → رباتت → **API Token** →
   **Revoke current token**
2. توکن جدید را در متغیر محیطی `BOT_TOKEN` سرویس جدید بگذار (یا داخل
   `manager_config.json`) و **Redeploy** بزن. فایل `manager_bot.string`
   را دست نزن؛ خودش با توکن جدید بازساخته می‌شود.
3. از این به بعد فقط سرویس جدید با تلگرام حرف می‌زند.

سمت کد: از نسخه‌ی `v0907` به بعد ربات هر دقیقه یک «ضربان» (beacon) در چت مدیر
می‌فرستد؛ اگر سرویس دومی ببیند خودش هشدار فارسی می‌دهد و سرویس اضافی را لو
می‌دهد. پیام «بالا آمد» هم شناسه‌ی نمونه (`نمونه ab12`) را دارد — اگر دو پیام
با شناسه‌های متفاوت می‌بینی یعنی هنوز دو سرویس روشن است.

### متغیرهای محیطی اختیاری

| متغیر | پیش‌فرض | کاربرد |
| --- | --- | --- |
| `DATA_DIR` | `/app` | پوشه‌ی داده (دیتابیس، `clients/`، نشست‌ها) |
| `JAFJ_IMAGE_DIR` | `/opt/jafj` | پوشه‌ی کد داخل ایمیج |
| `JAFJ_SUPERVISE` | `1` | `0` = بدون ری‌استارت خودکار (فقط `exec`) |
| `JAFJ_MAX_CRASHES` | `5` | چند کرش پشت‌سرهم تا تحویل به Railway |
| `JAFJ_LOGIN_RETRY` | خودکار | `off` = شکست ورود باعث exit شود |

### دروازه‌ی عملکرد (OpGate)

`CheckGate` فقط «بررسی عضویت» را پخش می‌کند؛ ولی سلف هم‌زمان جوین/لفت، ارسال
پیام و اسکن گروه هم می‌زند. دروازه‌ی عملکرد، فشارِ **کل** روی API تلگرام را
با واحدِ فشار در یک پنجره‌ی غلتان ۶۰ ثانیه‌ای حساب می‌کند (پیش‌فرض ۴۰ واحد
در دقیقه؛ جوین ۳، لفت/چک ۲، ارسال/اسکن ۱) تا مسیرهای نوشتنی پشت‌سرهم
FloodWait نخورند. چند فلود پشت‌سرهم هم «حالت سکوت» ۱۵ دقیقه‌ای می‌سازد و بعد
از ۱۰ دقیقه بی‌فلودی، بودجه پله‌پله برمی‌گردد.

| دستور | کار |
| --- | --- |
| `تبادل دروازه` | وضعیت: فشار پنجره، جریمه، فلودها، سکوت |
| `تبادل دروازه خاموش` / `روشن` | غیرفعال/فعال کردن (پیش‌فرض روشن) |
| `تبادل دروازه بودجه 60` | چند واحد فشار در دقیقه مجاز باشد |
| `تبادل دروازه فاصله 0.8` | حداقل فاصله‌ی سراسری بین دو عملیات |
| `تبادل دروازه ریست` | صفر کردن جریمه/سقف فلود/سکوت |
